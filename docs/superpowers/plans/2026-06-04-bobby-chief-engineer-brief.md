## 3. 本阶段使命与派单顺序
1. **PORT-0 先修**（禁令接进 `gate.evaluate`）——最高优先，否则产品"不许违禁"的承诺是空的。
2. **PORT-A**（分模型编码提示词，纯文本、最快见效、同时打三个敌人）。
3. **并行派发**：PORT-C（前缀缓存）/ PORT-F（意图分流）/ PORT-H（快照回滚）/ CLI-1（Ink 基座）。
4. **有序**：PORT-B（升级链）→ 然后 PORT-D（难度预算）、PORT-E（测试回灌）。
5. **压轴**：PORT-G（声明式子 agent，最大）。
6. CLI-2~6 在 CLI-1 之后并行；CLI-7（流式）最后且可降级。

## 4. 不可逾越的护栏（违反即打回，无论测试是否碰巧绿）
- **完成闸门是判定 `done` 的唯一权威**：升级 / 分流 / 快照 / 自查 / 子 agent 都不得让"未过闸门"的任务显示 `done`。
- **出题人 ≠ 阅卷人**：工人写实现、你独立验收；子 agent 只产**补丁提案**，过闸门 + Pro 复核 + 人确认才合并，**不能自批**。
- **验收只认真实证据**：工人交"摘要 / 我觉得可以 / 理论上通过"一律打回，要整段真实测试输出。
- **意图分流**：模棱两可默认按 TASK；**任何会改文件的请求绝不能走快路绕过闸门**。
- **CLI**：不引入 Deep Code 的 TUI；UI 只消费 `KernelHost` 事件 + 回发命令，零业务逻辑。
- **DeepSeek 协议细节**（模型 ID / SSE 流式 / FIM / 缓存 / reasoning）：先用 `bobby probe` 核实，**严禁臆测写死**。
