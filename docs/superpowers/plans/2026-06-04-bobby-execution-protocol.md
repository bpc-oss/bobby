# Bobby v1 — 执行协议（GPT-5.5 总工程师 × 5.3-codex-spark 工人）

> 把 老施 的执行分工映射到本施工图套件上，并植入一条铁律，**防止"建造 Bobby 的过程本身"重蹈 Bobby 要根治的病**。
> 配套：总纲 `2026-06-04-bobby-v1-master-plan.md` + M0–M8 子计划。

---

## 0. 核心风险与铁律（先读，最重要）
> **递归陷阱**：你在用 AI 工人造一个"专治 AI 说谎"的工具。若总工程师只凭工人一句"我做完了"就验收，**Bobby 要根治的"蒙混过关"会先在它自己的建造过程里得逞**。

**执行铁律（= 把 Bobby 的 L1/L2 用在建造上）：**
1. **总工程师绝不接受工人的"我做完了"作为完成依据。** 验收 = 总工程师**亲自跑**该 Task 的测试/命令、看**真实输出**。
2. **出题人 ≠ 阅卷人**：工人写实现，总工程师独立验收，不许工人给自己鸣哨。
3. **证据 > 说辞**：工人任何"我觉得可以 / 理论上通过 / 应该没问题"，一律视为**未完成**，打回要真实输出。

## 1. 角色映射
| 角色 | 模型 | 职责 |
|---|---|---|
| **总工程师** | GPT-5.5 | 读总纲；按里程碑顺序派单；**亲自验收**；判重做；管接线点与合并提交 |
| **工人** | 5.3-codex-spark | 接**单本 Task**；严格 TDD；回传 diff + **真实测试输出** |

施工图就是按"一个 Task = 一个可独立派发的工单"设计的；每个 Task 自带文件清单、逐步代码、可跑命令与预期输出。

---

## 2. 派单模板（总工程师 → 工人，每个 Task 一单）
每单必须自包含（**假设工人零上下文**）：
```
[任务] <里程碑>/<Task N 标题>
[范围] 只做这一个 Task，严禁扩大范围
[文件] <照抄计划里的 Create/Modify/Test 路径>
[步骤] 严格按计划 Step 1..N：写失败测试 → 跑→确认失败 → 写最小实现 → 跑→确认通过 → 提交
[完成时必须回传]
  1) git diff（完整）
  2) 测试命令的“整段真实输出”（不许摘要、不许转述、不许“大意是通过”）
  3) 你改动的文件清单
[红线]
  - 不许改其它 Task 的文件
  - 不许删改/放宽测试来“凑绿”
  - 不许在缺真实输出的情况下声称通过
```

---

## 3. 验收闸门（总工程师，每个 Task）—— 这就是建造版的"完成闸门"
总工程师**不看工人的话，只验证据**，按序执行，任一不过即重做：
1. 在干净工作区**应用工人的 diff**。
2. **亲自跑**该 Task 计划里写明的测试/命令，确认**真实 PASS**（对照计划的 Expected）。
3. 跑 `pnpm lint && pnpm -r build`，确认未引入坏味/未破坏构建。
4. **审 diff 防作弊**：是否只动了该 Task 声明的文件？`*.test.ts` 是否被偷偷改弱？（测试文件的每一行改动都要看）
5. 全过 → 接受、合并、进下一 Task。
> 没有"总工程师亲自跑出来的真实 PASS"，该 Task 一律视为未完成——哪怕工人发誓做完了。

---

## 4. 重做协议（不行 → 重做 → 完美）
不通过时，总工程师把**失败证据本身**当作重做规格发回：
```
[重做] <Task>
[失败证据] <粘贴真实失败输出：测试报错 / lint 报错 / 越界文件清单 / 被偷改的测试 diff>
[要求] 只修这个失败；不许改测试来糊弄；回传新的“整段真实测试输出”
```
- 设**重做上限**（建议 3 次）。超限 → 升级：总工程师亲自接管该 Task，或把它拆得更小再派。
- 这一步对应 Bobby 的 §6.9："失败不许静默改写成成功"。

---

## 5. 里程碑闸门（总工程师）
一本里程碑的全部 Task 被接受后，总工程师**整本复跑**：
- `pnpm -r test` 全绿；
- 该里程碑末尾"✅ 验收标准"逐条勾掉；
- **M2（良心）与 M6（三敌人回归集）的对抗用例必须真实跑过**——这是产品魂，谁都不许跳。

全绿才解锁下一里程碑。

---

## 6. 顺序与并行（派单节奏）
```
M0 → M1 → M2（魂，先打透）
              ├─ M3、M6 可并行派发（彼此独立的 Task）
              └─ M2/M3 就绪 → M4 ∥ M5
→ M7 → M8
```
- 并行时，总工程师负责合并冲突，并亲手接好总纲里的**组装根 + 3 个接线点**（KernelHost 装配 conscience+tools、编排器禁令校验、持久禁令/追问）。

## 7. 给总工程师的硬性提醒
- **⚠️ DeepSeek 协议项**：先派 **M6 Task 1 能力探针**，用真实结果回填模型 ID/能力开关；**严禁**让工人凭空写模型 ID、tool calling 字段、base URL（否则就是在源头制造幻觉）。
- **验收用真实输出**：工人回传"摘要"不算数；要 stdout/exit code 原文。
- **测试即规格**：重做时不要描述"应该怎样"，直接给失败测试输出，让工人对着它修。
